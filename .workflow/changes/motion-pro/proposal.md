## Current behavior and decision

The timeline on this base opens through `src/components/motion/MotionTimeline.tsx:48`. The pro panel, its serialized writer and its keyboard/viewport tests exist on the local UI branch. Integrate that work, then repeat its review with the default canvas panels visible. The editor does not yet provide the live element-effects compositor scheduled for M1. Expose the difference between editing a persisted stack and seeing an effect on a supported render target.

`server/motionSnapshot.ts:362` reads a stored composition, runs its lint and reports per-track costs, total, cap, and effects the renderer drops. Normal editing rejects an unknown effect or invalid value before persistence. A valid-document-only test cannot demonstrate AC-11. `shared/motionLint.ts:40` and line 41 already assign MO-13 to dangling lanes and MO-14 to undrawn effects. Existing consumers depend on these meanings.

## Contract and implementation decisions

- Keep `EffectInstance`, the registry, the eight built-in look bundles and the revisioned composition patch as the common data model. The panel derives defaults, ranges and cost from shared code. A look creates an editable adjustment track. Changing its stack does not change a catalog entry.
- Extend the scene check with an optional candidate effect stack for one named track. This additive, read-only input enables diagnosis before a write. Validate the bounded candidate shape before resolving its effect/param values. Report unknown IDs and invalid ranges separately, with track, instance and parameter where available. Keep the stored composition and its cost report unchanged when the candidate is invalid. Include a stable diagnostic kind alongside each historical rule family to distinguish the new diagnostic from its existing meaning. Keep normal composition writes strict.
- Share the input and result between the MCP registration and resident dispatcher; document the new optional field, reason codes and a valid and invalid example. Missing canvas access follows the existing scene-check policy. A missing track returns a named input error. The ordinary no-candidate call stays compatible.
- Use UI branch `MotionProPanel`, `EffectCatalog`, `EffectStack`, `EffectParams` and `CostMeter` inside the timeline. Four tabs expose Effects, Looks, Film and Direction. Keep controls available in the compact overlay, show the actual pressed state and associate a visible explanation with disabled actions. Both languages use their existing message catalogs and design tokens.
- Route every edit through the revision-aware writer. Preserve adjacent edits by re-resolving IDs after a conflict. A failed undo remains on its original stack with a visible notice. Coalesce repeated input to one user action. Inverses address only the field or effect the person changed. Redo of a removed effect preserves its keys.
- No new table, migration, worker, shell command or provider. Rendering reuses `src/lib/motion/compositor.ts`, `src/lib/motion/gl.ts` and `src/pages/MotionRenderHarness.tsx`. Browser proof requires a working Chromium GL backend. Preserve explicit drops when GL is unavailable. Broader compositor changes belong to the layer editor and later M2–M5.
- D1. Proposed diagnostic input is an optional candidate stack rather than allowing corrupt compositions to persist. D2. Keep the existing family names with disambiguating machine kinds until a separately reviewed protocol change. D3. Keep blend controls with an accessible reason wherever the renderer cannot honor them. The UI branch is an input to review and has no integration or release evidence on this base.
